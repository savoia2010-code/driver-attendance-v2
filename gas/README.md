# GASバックエンド デプロイ手順

`code.gs` は本アプリのGoogle Apps Scriptバックエンドの完全な実装です。
mock-server と同一のAPI仕様（`{action, ...params}` のPOST）で、以下を備えています：

- **LockService による同時書き込み保護**（複数ユーザーが同時に保存しても行の二重追加・消失が起きない）
- **savedAt による楽観的競合検知**（mock-server と同一仕様）
- **3層の認可モデル**（機密値はすべてスクリプトプロパティから取得。コードに直接書かない）
  1. アプリ共通トークン（`ACCESS_TOKEN`）… bot除け程度。config.js は公開されるため秘密ではない
  2. ドライバー個人トークン（`url_token`）… 記録の読み書きは**管理者または本人のみ**。専用URL `?token=〜` で配布
  3. 管理者キー（`ADMIN_KEY`）… マスタ管理・全ドライバーの記録閲覧。総当たり対策（5回失敗で10分ロック）付き

## 運用ルール（重要）

- **各ドライバーには管理画面の「🔗 専用URL」ボタンでコピーしたURLを個別に配布**する
  （LINEなど本人にだけ届く手段で。URLを知っている人はそのドライバーの記録を読み書きできる）
- URLを配布し直したい・漏れた疑いがある場合は「♻ 再発行」で旧URLを無効化できる
- 管理者は `?mode=admin` でアクセスし、管理者キーを入力する（キーはブラウザに保存されない）
- 専用URLなしで開いた場合、画面は表示されるが記録の読み書きはサーバー側で拒否される

## 既存のGASコードがある場合

既にGASを運用中でシート構造が異なる場合は、そのままこのコードに置き換えるとデータが読めなくなります。
既存の `.gs` ファイルをこのフォルダにコピーして共有してください。既存のシート構造に合わせて
LockService・競合検知・認証チェックを組み込みます。

## 新規デプロイ手順

### 1. スプレッドシートを用意
1. Google Sheets で新しいスプレッドシートを作成（または既存のものを使用）
2. URLの `/d/` と `/edit` の間の文字列（スプレッドシートID）を控える
   - 例: `https://docs.google.com/spreadsheets/d/【この部分】/edit`
3. シート（drivers / checkers / records）は初回アクセス時に自動作成される
   - drivers シートにドライバーを事前登録する場合は、1行目にヘッダー `id | name | url_token`、2行目以降にデータを入力

### 2. Apps Script プロジェクトを作成
1. スプレッドシートの「拡張機能 → Apps Script」を開く
2. `code.gs` の内容を全部貼り付けて保存

### 3. スクリプトプロパティを設定
「プロジェクトの設定（歯車アイコン）→ スクリプトプロパティ」で以下を追加：

| プロパティ名 | 値 |
|---|---|
| `SPREADSHEET_ID` | 手順1で控えたスプレッドシートID |
| `ACCESS_TOKEN` | 任意の長いランダム文字列（例: パスワード生成ツールで32文字） |
| `ADMIN_KEY` | 管理者モードのキー（管理者が入力する値） |
| `MONTHLY_SPREADSHEET_ID` | 事務所用の月次シートを書き出す**別の**スプレッドシートのID（下記「事務所用 月次シート」参照。使わないなら省略可） |

### 4. ウェブアプリとしてデプロイ
1. 「デプロイ → 新しいデプロイ → 種類: ウェブアプリ」
2. 「次のユーザーとして実行」= **自分**
3. 「アクセスできるユーザー」= **全員**
4. デプロイして表示されたURL（`https://script.google.com/macros/s/.../exec`）を控える

### 5. フロントエンドの config.js を設定
```js
const CONFIG = {
  GAS_URL:   'https://script.google.com/macros/s/【デプロイID】/exec',
  APP_TOKEN: '手順3の ACCESS_TOKEN と同じ値',
};
```
※ config.js はリポジトリに含まれ、GitHub Pages 経由で公開される。
ここに書く GAS_URL・APP_TOKEN は秘密として扱えない（上記「認可モデル」の第1層の位置づけ）。
実際の保護はドライバー個人トークン（url_token）と ADMIN_KEY が担う。

### 6. 動作確認
1. ブラウザで GAS_URL を直接開く → `{"status":"ok"}` が表示されればデプロイ成功
2. アプリを開いてドライバー一覧が表示されることを確認
3. 打刻→スプレッドシートの records シートに行が追加されることを確認

## 事務所用 月次シート（generateMonthlySheets）

事務所が月次の勤怠集計に使っている形式（1タブ＝ドライバー1人×締め期間1か月、A〜EU の151列）を、
アプリ直結のスプレッドシートとは**別ファイル**に書き出す機能。

- **準備**：共有ドライブに空のスプレッドシート（例「月次集計」）を作り、そのIDをスクリプトプロパティ
  `MONTHLY_SPREADSHEET_ID` に設定する。アプリ直結のシート（`SPREADSHEET_ID`）とは必ず別にすること
- **使い方**：管理者モードで「月次」タブ → 📊 → 期間を選び「📗 事務所用シートに出力（全員）」。
  自動では動かない（押したときだけ生成）。期間はPDFと同じ締め期間（26日〜翌25日）
- **タブ名**：`YY/MM/氏名`（締め月。例 `26/10/橘高`）。その期間に記録が無いドライバーは省略される
- **再生成**：同じタブがあれば作り直す。ただし「仮受金・本日送金高・差引手持高」の3列は
  アプリに入力欄が無く事務所が手入力するため、同じ日付の値を引き継ぐ。それ以外の手直しは消える
- **小計・合計行は数式**（小計＝宿泊費＋手当。アプリの月次PDFと同じ）。時間列は `h:mm` 表示の時刻値

## コードを更新するとき

`code.gs` を修正したら、GASエディタに貼り付け直して
「デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン」で更新する。
（「新しいデプロイ」にするとURLが変わってしまうので注意）

## 通信仕様のメモ

- フロントは `Content-Type: text/plain` でPOSTする（`application/json` だとブラウザが
  CORSプリフライト（OPTIONS）を送るが、GASはこれに応答できず通信が失敗するため）
- GAS側は `e.postData.contents` をJSONとして解釈する
- 全リクエストに `token` フィールドが付き、スクリプトプロパティ `ACCESS_TOKEN` と照合される
  （`ACCESS_TOKEN` 未設定の場合はチェックをスキップ＝開発用）
